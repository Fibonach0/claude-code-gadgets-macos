# Casos del detector de credenciales.  esperado|archivo|texto
#
# Las claves NO se escriben acá: van como marcas (%ANTHROPIC%, %SLACK%…) y el
# script las arma al azar en cada corrida. Así el hook ve una credencial
# completa y de verdad, y el repositorio no guarda nada que parezca una — que
# es exactamente lo que este hook viene a evitar, y lo que el escáner de
# GitHub frenó cuando estaban escritas enteras.
MAL|repo/config.py|ANTHROPIC_KEY = "%ANTHROPIC%"
MAL|repo/deploy.sh|export AWS_ACCESS_KEY_ID=%AWS%
MAL|repo/.github/ci.yml|token: %GITHUB%
MAL|repo/notas.md|el de slack es %SLACK%
MAL|repo/app/db.py|DSN = "postgresql://admin:%CLAVE%@db.interno:5432/app"
MAL|repo/lib/auth.js|const t = "%JWT%"
MAL|repo/claves/id_rsa|-----BEGIN OPENSSH PRIVATE KEY-----
MAL|repo/front/firebase.js|apiKey: "%GOOGLE%"
BIEN|repo/config.py|ANTHROPIC_KEY = os.environ["ANTHROPIC_API_KEY"]
BIEN|repo/.env.example|SUPABASE_SERVICE_KEY=tu-clave-de-servicio-acá
BIEN|repo/README.md|Poné la clave en la variable SUPABASE_SERVICE_KEY de Railway, nunca en el repo.
BIEN|repo/docs/guia.md|El token se ve como sk-ant-… (acortado a propósito)
BIEN|repo/app/db.py|DSN = os.environ["DATABASE_URL"]
BIEN|repo/front/config.js|const url = "https://miapp.ejemplo.com/api"
BIEN|afuera/token|%ANTHROPIC%
COMMIT|repo/config.py|SUPABASE_SERVICE = "%SUPABASE%"
